THREAT HUNTING · INTERMEDIATE

From Hypothesis → Telemetry → Detection

A practical threat hunting workflow begins with a falsifiable hypothesis. From there, identify the telemetry needed to validate it, investigate anomalies, map behavior to ATT&CK and turn confirmed behavior into a reusable detection.

1. Start with a hypothesis

Example: suspicious PowerShell execution may indicate execution, persistence or payload delivery activity. Define what evidence should exist if the hypothesis is true.

2. Identify data sources

Windows process creation, PowerShell logs, network telemetry, EDR events and authentication activity can provide complementary evidence.

3. Investigate and map behavior

Correlate timestamps, users, hosts, parent-child processes, command lines and network destinations. Map confirmed behaviors to ATT&CK rather than mapping every suspicious event automatically.

4. Engineer the detection

Turn high-confidence patterns into Sigma/SPL logic, then test the detection against expected benign activity and tune false positives.

Research principle: Don't hunt for alerts. Hunt for behaviors.
